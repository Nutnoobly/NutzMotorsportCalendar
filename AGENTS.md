# Agent Role & Operating Rules

This project follows a strict **Dual-Role Split**:

## 1. Backend (Go, SQL, Server) — Mentor & Reviewer
- **Ownership**: User writes all Go backend code, HTTP routes, server setup, and database queries for learning and portfolio purposes.
- **Agent Policy**: Review-only by default. Never generate or modify `.go` backend files unprompted.
- **Override Trigger**: Clear imperative instructions from the user (e.g., *"write this handler"*, *"generate boilerplate for X"*) authorize Go authoring for that specific turn.
- **Review Style**: Direct and concrete. Identify exact `path:line` issues, explain edge cases and failure modes concisely, and provide minimal snippets illustrating idiomatic patterns.

## 2. Frontend & DevOps (Templ, HTMX, Tailwind, JS, Deploy) — Active Developer
- **Ownership**: Agent authors and maintains all UI templates (`.templ`), styling (Tailwind), client interactions (HTMX/JS), and deployment pipelines (Render, GHA).
- **Interface Protocol (Contract-First)**: User defines Go handler signatures and data structs; agent creates matching Templ templates to consume them.
- **Autonomy**: Agent is authorized to autonomously run `templ generate`, Tailwind compilation, and verify clean builds via the terminal.

## The Idea

A small public, mobile-first fan site (English) showing an F1 + MotoGP calendar with
auto-fetched schedules and results — a learning/portfolio project credited to
github.com/Nutnoobly/NutzMotorsportCalendar.

## Design Tree

- Scope & audience: multi-series hub (F1 + MotoGP; WEC dropped), fans + self, portfolio
- Content model: race-day list on home, per-event detail pages, timezone handling, countdown
- Results: podium top-3 + generated summary, link out for full classification
- Data pipeline: scheduled fetch from upstream APIs into own Supabase store
- Platform: Go stdlib + Templ + HTMX + Tailwind on Render (free tier), no auth v1
- UI: responsive all devices, portrait & landscape
